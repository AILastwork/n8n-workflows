# my-itnews-autopost

Автопостинг новостей в Telegram-канал [@My_ITnews](https://t.me/My_ITnews):
раз в полчаса берётся свежая запись из одного RSS-источника, модель
пересказывает её по-русски, результат проверяется и уходит в канал.

Файл воркфлоу: [`../workflows/my-itnews-autopost.json`](../workflows/my-itnews-autopost.json)

## Схема

```
Schedule Trigger
      │
Pick Source          выбор источника по времени суток
      │
RSS Read             чтение ленты
      │
Limit                берём одну запись
      │
Remove Duplicates    отсев уже опубликованного по guid
      │
Basic LLM Chain      пересказ на русском (OpenRouter)
      │
Guard Output         проверка текста
      │
Публиковать?         ┌── ok=true  → Send a text message  → канал @My_ITnews
                     └── ok=false → Alert Ops → Send Ops Alert → тема «Операции»
```

## Расписание

Cron `0,30 9-22 * * *` в часовом поясе контейнера (Europe/Moscow) —
каждые полчаса с 9:00 до 22:30 МСК, 28 слотов в сутки.

Каждому слоту в `Pick Source` соответствует свой источник, поэтому ленты
чередуются и один ресурс не занимает несколько публикаций подряд.

## Источники

14 RSS-лент: OpenAI, Google AI, Anthropic, Hugging Face, GitHub Changelog,
TechCrunch AI, The Verge, Habr Develop, The Hacker News, Krebs Security,
Bleeping Computer, Habr Admin, Kubernetes, Docker.

## Защита от повторов

`Remove Duplicates` работает в режиме `removeItemsSeenInPreviousExecutions`
по полю `guid`, история — 10 000 записей. Если новость уже публиковалась,
элемент отбрасывается и слот пропускается.

## Модель

`meta-llama/llama-3.3-70b-instruct` через OpenRouter, `temperature` 0.3,
`maxTokens` 700. Промпт требует пересказ по-русски в формате канала:
заголовок, 2–4 пункта, блок «почему это важно», ссылка на первоисточник,
хештеги. Разметка — HTML (Telegram `parse_mode: HTML`).

## Guard Output — почему он появился

17.09.2026 модель вернула вырожденный ответ: 2711 символов, из них 2682 —
обратные слэши, ноль кириллицы. Узел Telegram отправил это в канал и отчитался
об успехе: с точки зрения n8n сбоя не было — модель ответила, отправка прошла.
Мусор увидел владелец канала.

Между моделью и отправкой поставлен узел-проверка. Он не исправляет текст и
ничего не подменяет: либо пропускает как есть, либо помечает отбраковку
с причиной.

Признаки, по которым текст не допускается к публикации:

| Проверка | Порог |
|---|---|
| Длина | вне 200–3500 символов |
| Кириллица | меньше 100 символов |
| Уникальные символы | меньше 25 |
| Доля самого частого символа | больше 25% |
| Повтор одного символа подряд | 30 и более |
| Пустой ответ или отсутствующее поле | отбраковка |
| Парность HTML-тегов | число открывающих ≠ числу закрывающих |

Последняя проверка закрывает отдельный класс сбоев: 16.09 три запуска упали с
`can't parse entities` — модель открывала `<b>` и не закрывала его, и Telegram
отбивал сообщение целиком.

Теги, не входящие в список разрешённых Telegram (`b`, `strong`, `i`, `em`, `u`,
`s`, `code`, `pre`, `a`, `blockquote`), экранируются — случайный `<script>` в
тексте становится безопасным, а не ломает отправку.

Код узла: [`../nodes/guard-output.js`](../nodes/guard-output.js)

## Поведение при отбраковке

**В канал не уходит ничего.** Слот пропускается, следующая попытка — по
расписанию через полчаса.

Сообщение о причине уходит в тему «Операции» (`message_thread_id: 14`) рабочей
группы: причина отбраковки, источник, заголовок новости и ссылка на
первоисточник — чтобы решить, стоит ли публиковать вручную.

В выгруженном файле id этой группы заменён на `<OPS_GROUP_CHAT_ID>`.

Код узла: [`../nodes/alert-ops.js`](../nodes/alert-ops.js)

## Устойчивость к сетевым сбоям

На узле отправки в канал включён повтор: 3 попытки с паузой 3 секунды.
Guard защищает от плохого содержимого, но не от временной недоступности
Telegram — это разные отказы.

## Что остаётся незакрытым

`errorWorkflow` в настройках воркфлоу не задан: если упадёт сам узел модели
или чтение RSS, уведомления не будет — запуск просто окажется в истории
со статусом `error`.

## Учётные данные

| Узел | Учётные данные n8n |
|---|---|
| Send a text message | Telegram: `Antology_service_bot` |
| Send Ops Alert | Telegram: `Antology_service_bot` |
| OpenRouter Chat Model | OpenRouter |

Значения ключей в репозиторий не выгружаются — в файле остаются только `id`
и название. После переустановки n8n учётные данные создаются заново, а в
импортированном воркфлоу их нужно выбрать вручную.
