# n8n-workflows

Воркфлоу n8n для автоматизаций Antology Service, выгруженные из рабочего
экземпляра. Репозиторий — история изменений и способ восстановить автоматизацию,
если n8n придётся поднимать заново.

## Что здесь

| Путь | Что это |
|---|---|
| `workflows/` | Выгруженные воркфлоу в формате импорта n8n |
| `docs/` | Как устроен каждый воркфлоу и почему сделано именно так |
| `nodes/` | Код узлов-функций отдельными файлами (удобно читать и править) |
| `export_workflows.py` | Выгрузка из n8n с вычисткой чувствительного |

## Секреты

В репозитории их нет и быть не должно.

Воркфлоу ссылаются на учётные данные n8n по `id` и названию — сами ключи
остаются в n8n и в файле секретов на сервере. Скрипт выгрузки вырезает блоки
`credentials.*.data` и `pinData`, заменяет идентификаторы приватных чатов на
плейсхолдеры и проверяет результат на типовые шаблоны ключей (Telegram,
OpenRouter, Яндекс, JWT, приватные ключи). Если что-то найдено — выгрузка
прерывается.

Та же проверка стоит в `pre-commit` хуке, поэтому коммит с секретом не пройдёт.

Проверить репозиторий вручную:

```bash
python3 export_workflows.py --check
```

## Плейсхолдеры в файлах

| Плейсхолдер | Что подставить при импорте |
|---|---|
| `<OPS_GROUP_CHAT_ID>` | id группы, куда уходят сообщения об отбраковке |

## Как обновить выгрузку

```bash
export N8N_URL="http://адрес-вашего-n8n:5678/api/v1"
python3 export_workflows.py          # тянет из n8n и пишет в workflows/
git diff                             # смотрим, что изменилось
git add -A && git commit -m "..."    # коммитим осмысленным сообщением
```

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `N8N_URL` | адрес API n8n, по умолчанию `http://127.0.0.1:5678/api/v1` |
| `N8N_API_KEY` | ключ API напрямую |
| `N8N_SECRETS_FILE` | файл со строкой `N8N_API_KEY=...`, если ключ не задан переменной |
| `OPS_GROUP_CHAT_ID` | id приватной группы, который будет заменён плейсхолдером |

Приватные значения не хранятся в самом скрипте — он берёт их из окружения,
поэтому в репозитории их нет даже в коде выгрузки.

## Как восстановить воркфлоу в n8n

1. Создать учётные данные в n8n вручную (Telegram-бот, OpenRouter) — по названиям
   из файла воркфлоу.
2. Импортировать JSON: **Workflows → Import from File**.
3. Открыть узлы с учётными данными и выбрать созданные на шаге 1 —
   `id` из файла после переустановки n8n не совпадёт.
4. Проверить расписание и включить воркфлоу.
